# 评审博客文章

评审中文博客文章质量，输出改进意见，然后自动调用重构流程完成改进。

## 输入

用户指定文章路径，如 `content/posts/2022-08-08-openssl-rsa.md`

## 评审维度

对文章从以下 5 个维度打分 (1-5) 并给出具体改进意见：

### 1. 结构
- 是否有清晰的问题陈述/引入？
- 段落层次是否合理？H2/H3 使用是否得当？
- 是否有结论/收尾？
- 信息密度是否均匀？

### 2. 深度
- 是否只停留在 "怎么做"，还是解释了 "为什么"？
- 关键技术点是否有原理性解释？
- 是否有作者自己的洞察/判断？
- 是否引用了权威来源佐证？

### 3. 简练
- 是否有冗余表述、废话、口水话？
- 能否用更少的文字传达相同信息？
- 代码示例是否精简到位？
- 是否有不必要的上下文铺垫？

### 4. 实用性
- 读者看完能否直接动手？
- 关键信息（版本号、命令、配置）是否完整？
- 是否有常见坑点提示？
- 代码是否可直接运行？

### 5. 格式
- Front matter 是否规范？
- 代码块是否标注语言？
- 链接是否有效且有价值？
- Markdown 格式是否整洁？

## 输出格式

```markdown
## 评审报告: <文章标题>

### 评分

| 维度 | 分数 | 说明 |
|------|------|------|
| 结构 | X/5 | ... |
| 深度 | X/5 | ... |
| 简练 | X/5 | ... |
| 实用性 | X/5 | ... |
| 格式 | X/5 | ... |
| **总分** | **X/25** | |

### 具体改进意见

1. ...
2. ...
3. ...

### 建议补充的引用

- [链接](url) — 原因
```

## 工作流程

1. 读取并分析文章
2. 按 5 个维度评审，输出评审报告
3. 如果总分 < 20/25，将改进意见作为上下文，直接执行 `/refactor-post` 对该文章进行重构
4. 重构时将评审意见作为额外约束传入，确保所有改进点被落实
5. 如果总分 >= 20/25，只输出评审报告，跳过重构

## 注意事项

- 只处理中文版本（`.md`，不处理 `.en.md`）
- 评审后触发的重构不再重复评审（避免循环）
- 保留作者原始观点和代码逻辑，改进的是表达而非内容本身
