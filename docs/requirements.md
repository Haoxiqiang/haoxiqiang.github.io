## 设计风格需求

### 期望风格关键词

- **极简** — 去除不必要的视觉元素
- **技术感** — 等宽字体在代码区域，细线条/几何元素
- **留白** — 内容呼吸感，不拥挤
- **专注内容** — 文字是核心，减少干扰
- **暗色友好** — 暗色模式下同样优雅

## 迁移考量

### 已有文章兼容性

| 项目 | 现状 | 迁移影响 |
|------|------|----------|
| Markdown 内容 | 标准 Markdown + 少量 HTML | 基本兼容所有 SSG |
| Front matter | YAML，字段不统一 | 需要统一标准化 |
| 图片引用 | `/images/` 路径，部分可能缺失 | 需要整理迁移 |
| 代码块 | ````lang` 标准格式 | 完全兼容 |
| URL 结构 | `/posts/:title/` | 迁移时需要保持或做重定向 |
| 分类/标签 | 格式不统一 | 需要清理统一 |

### 迁移工作量估算

| 方案 | 工作量 | 风险 |
|------|--------|------|
| 升级 Chirpy (原地优化) | 低 (1-2h) | 极低 |
| 迁移到 Hugo PaperMod | 中 (4-8h) | 低 — URL 可能变化 |
| 迁移到 Astro | 高 (1-2d) | 中 — 需要适配内容集合 |

## 结论

**推荐方案：Hugo + PaperMod**

- 最符合"简单优雅、体现技术范"的需求
- 迁移成本可控 (半天工作量)
- 构建速度极快，长期维护舒适
- 如果偏好低成本启动，升级当前 Chirpy 也是很好的选择，已有的配置基础扎实

下一步：确认选择方案后，可以开始实施迁移或升级。
